# Solver preset: PCBDDC iterative solver (FGMRES on the MATIS operator with the
# exact Nedelec discrete-gradient coarse space).
# Usable by both kernels. Add it after the case config, e.g.:
#   build/im.csem -options_file configs/params_im.txt   -options_file configs/solver_bddc.txt
#   build/fm.csem -options_file configs/params_fm_f1.txt -options_file configs/solver_bddc.txt
-dm_mat_type                 is
-ksp_type                    fgmres
-pc_type                     bddc
-pc_bddc_use_deluxe_scaling  1
-pc_bddc_coarse_pc_type      lu
# Treat the operator as a single field. Redundant with the explicit
# PCBDDCSetDofsSplittingLocal call in setupBDDCFromPetgemGradient (src/solver.c),
# kept here as documentation and as a safety net for any path that reaches
# PCBDDC through the options database alone.
#
# Why it matters: DMCreateMatrix leaves a DM attached to the MATIS operator, so
# BDDC calls DMCreateFieldDecomposition, and DMPlex tags the field IS with
# block size = DOFs per edge (= order). BDDC reads that as a field COUNT, so at
# order >= 2 PCBDDCNedelecSupport only sees one DOF per geometric edge and
# aborts with "Unexpected SIZE OF EDGE > EXTCOL SECOND PASS". Forcing a single
# field makes the Nedelec coarse-edge construction see the full edge DOF set.
# (Diagnosis confirmed by the PETSc team; a Plex-side fix may land upstream.)
-pc_bddc_monolithic
