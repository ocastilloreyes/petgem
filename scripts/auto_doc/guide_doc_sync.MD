# DOCUMENTATION SYNC SYSTEM DOCUMENTATION

This document explains how to use the automatic synchronization system between the `README.rst` file and the documentation generated by Read the Docs.

**Objective:**

To allow the `README.rst` to be the primary source of content for certain sections of the documentation, controlling what is included, where it goes, and how it appears in the table of contents (`toctree`) using special directives embedded as comments in the `README.rst`.

**How It Works:**

A Python script (`sync_rtd_docs.py`) parses the `README.rst` searching for special directives. Based on these directives, it extracts sections from the `README.rst`, formats them, and creates or updates individual `.rst` files in the documentation directory. Additionally, it updates the main `toctree` file (usually `index.rst`) to include these generated sections.

**Configuration Directive: `rtd-sync-config`**

To control how a section of the `README.rst` is processed, you must place an `.. rtd-sync-config::` directive as a reStructuredText comment *immediately before* the header of the section you wish to manage.

**Syntax:**

```rst
.. rtd-sync-config::
   :param1: value1
   :param2: value2
   ...

Section Title in README
=======================
Section content...
```

**Available Parameters for `rtd-sync-config`:**

*   **`:target: <path/to/file.rst>`**
    *   **Required** (unless `:skip:` is present).
    *   Specifies the relative path (from the project root or the `docs/` folder) where the content of this section will be saved.
    *   Example: `:target: features/list.rst`

*   **`:title_in_doc: "Title for Documentation"`**
    *   Optional.
    *   The title that will be used for this section within the generated `.rst` file.
    *   If omitted, the exact title of the section as it appears in `README.rst` will be used.
    *   Useful if you want a more descriptive or different title in the formal documentation.
    *   Example: `:title_in_doc: Detailed Feature List`

*   **`:toctree_entry: "Name in Index"`**
    *   Optional.
    *   The text that will be used for this section in the `toctree` of the `index.rst` file.
    *   If omitted but the section is processed (and has a `target`), the `title_in_doc` (if it exists) or the README title will be used as the `toctree` entry. The reference in the `toctree` will be the `target` path without the `.rst` extension.
    *   To omit a section from the main `toctree` but still generate the file, you can leave the value empty or use a special value that the script ignores (not implemented by default, but could be added).
    *   Example: `:toctree_entry: Key Features`

*   **`:skip:`**
    *   Optional (boolean parameter, its presence activates it).
    *   If this option is present, the `README.rst` section that follows it will be completely ignored by the synchronization script. No file will be generated for it, nor will it be included in the `toctree`.
    *   Useful for sections of the `README.rst` that are specific to the repository and should not go into public documentation.
    *   Example: `:skip:`

**Complete Example in `README.rst`:**

```rst
.. File: README.rst

Welcome to Project XYZ
######################
This is the main text of the README.

.. rtd-sync-config::
   :target: docs/introduction.rst
   :title_in_doc: Introduction to Project XYZ
   :toctree_entry: Introduction

Project Overview
================
This content will be copied to `docs/introduction.rst` and will appear in the index
as "Introduction". The title within `docs/introduction.rst` will be
"Introduction to Project XYZ".

.. rtd-sync-config::
   :target: docs/main_features.rst
   :toctree_entry: Features

Highlighted Features
--------------------
Features are listed here. The title in `docs/main_features.rst`
will be "Highlighted Features" (taken from the README) and in the index
it will appear as "Features".

.. rtd-sync-config::
   :skip:

Internal Notes for Developers
-----------------------------
This section will not be included in the Read the Docs documentation.

.. rtd-sync-config::
   :target: docs/petgem_specifics.rst
   :title_in_doc: What is PETGEM?
   :toctree_entry: PETGEM

PETGEM Specific Details
-----------------------
Information about PETGEM that will have a different title in the documentation.
```

**`index.rst` File (or your main `toctree` file):**

The script will look for special markers in your `index.rst` file (or the file you configure as `INDEX_FILE`) to know where to insert the generated `toctree`. You should prepare your `index.rst` like this:

```rst
.. File: docs/index.rst (or the configured path)

###################
Your Project Title
###################

Welcome to the XYZ documentation.

..
   AUTOGENERATED-TOC-START
   DO NOT MODIFY THIS SECTION MANUALLY. IT WILL BE REGENERATED BY THE SCRIPT.
..

.. toctree::
   :maxdepth: 2
   :caption: Main Content:

   // The script will fill this with entries from `toctree_entry`
   // or the filenames from `target`.

..
   AUTOGENERATED-TOC-END
..

More manual content from your index.rst can go here...

Manual Section
==============
This is a section untouched by the script.
You can also have manual entries in the toctree *outside* the markers,
or configure the script to preserve those within (more complex).
For now, the script will replace everything between the markers.
```

**How to Run the Script:**

1.  Ensure you have Python 3 installed.
2.  Save the script as `sync_rtd_docs.py` in the root of your repository (or wherever you prefer, adjusting paths if necessary).
3.  Configure the `README_FILE_PATH` and `INDEX_FILE_PATH` constants at the beginning of the script if your files are not named `README.rst` and `docs/index.rst` or are not in those relative locations.
4.  From the terminal, in the directory where the script is located:
    ```bash
    python sync_rtd_docs.py
    ```
5.  Review the generated changes (`git diff`) in your `docs/` folder and in `index.rst`.
6.  Commit the changes:
    ```bash
    git add .
    git commit -m "Synchronize documentation from README"
    git push
    ```
